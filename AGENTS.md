# AGENTS.md — filial-rails-core

Not Rails app. Thin orchestration wrapper. Manages Filial Rails via git worktrees. Provides per-worktree
**rootless podman** dev/test stacks as systemd user units (Quadlet) via mise tasks + shared Traefik proxy.
Repo history unrelated to app. (.container-config/ predates the podman conversion; the name stuck. There is
no Docker anywhere in the runtime — the last Compose version is tagged docker-final.)

> Read before touch .mise/, .scripts/, or .container-config/.

## Layout

- master/ — base worktree (has .git dir); canonical app.
- <slug>/ — linked worktrees (have .git file).
- .scripts/ — bash helpers (worktree actions, bootstrap, lib, newterm.sh terminal launcher).
- .dashboard/ — the web dashboard (Ruby, Roda + Falcon, minitest); a host process, see Dashboard below.
- .mise/config.toml — mise tasks + base env; local.toml.template rendered per worktree.
- .mise/tasks/ — task files: wt/rm, tags.
- .container-config/ — quadlet/ (unit templates, worktree + proxy), systemd/ (plain user-unit templates:
  dashboard.service), Dockerfile, Dockerfile.playwright, entrypoints, .env, initdb/, db-dumps/,
  firewall/ (egress firewall hook + allowlists), home-template/ (seeds .home/<slug>),
  status/ (git-ignored claude status files), git-hooks/ (backups of master/.git/hooks — see git-guard below).
- .firewall/ — (git-ignored) firewall runtime: hooks.d/ (hook descriptor rendered by units:install, the
  --hooks-dir every firewalled container passes), state/<container-id> (profiles, mode, resolved
  addresses; read by fw:show), hook.log.
- .unit-env/ — (git-ignored) <slug>.env per worktree, generated by units:env: every value the unit
  templates interpolate. A cache of .nvmrc/.ruby-version/Gemfile.lock/mise.local.toml, so
  lib.sh's ensure_unit_env regenerates it whenever one of those is newer (up, build, claude). Outside the worktree on purpose — a worktree is a checkout of the *app*
  repo, whose .gitignore this repo does not control, and this file holds POSTGRES_PASSWORD.
  <slug>.share.env alongside it is written by wt:share and is empty otherwise.
- .home/ — (git-ignored) per-worktree container home dirs, seeded from .container-config/home-template/.
- .container-config/claude-memory/ — (git-ignored) Claude's file memory, shared by every worktree
  container (host sessions keep their own); outside .home/ so wt:rm can't delete it.
- mise.local.toml — (root, git-ignored) set PROJECT_PREFIX, GEM_VOLUME_BASE, secrets.
- ports.registry — slug:WORKTREE_ID; source for port assignment.

## Worktree lifecycle

mise run wt <branch|PR#|new-branch> → .scripts/create-worktree.sh:

1. Resolve branch (PR# via gh), sanitize name (lower, no-alphanum→-, cap 40; hash suffix for collision).
2. git worktree add (local/remote branch or new from HEAD).
3. Allocate next WORKTREE_ID = max(registry)+1, append slug:ID to ports.registry (only after add succeeds).
4. Render mise.local.toml from .mise/local.toml.template (WORKTREE_ID).
5. Pre-create node_modules/ (prevent root ownership on mount).
6. Seed untracked files from master/ per .container-config/worktree-seed.txt.
7. mise trust -y && mise install in new dir.

mise run wt:rm <branch|dir> → .scripts/remove-worktree.sh: reject base;  
reject dirty worktree unless FORCE=1; stop the worktree's units (systemd owns the containers, so  
`podman stop` alone would let Restart=on-failure bring them back); remove its containers, its three  
volumes and its network **by exact name** — a `name=^<prefix>-<slug>-` filter is an unanchored regex  
and would sweep a sibling whose slug extends this one (api → api-v2); never images, which are shared  
across worktrees by runtime tag (that is `clean`'s job); delete .home/<slug>  
(guarded — holds a live Claude OAuth token, not just clutter); delete ports.registry line;  
remove mise trust symlinks; scoped `git worktree remove --force`  
(never a blanket `git worktree prune` — see Gotchas). Aborts up front if any registered worktree  
dir is missing (partial filesystem view, e.g. the container).

mise run wt:ls list worktrees; mise run wt:open [browser] open link.

mise run wt:share / wt:unshare → .scripts/share-worktree.sh: expose ONE worktree over the tailnet for
phone testing. tailscale serve fronts rails (:443) and rustfs (:8443), Traefik bypassed.
**Not by container IP**: tailscaled runs in the host network namespace and a rootless container's IP is
unreachable from there (podman-unshare(1): "otherwise not possible from the host network namespace").
Loopback-published ports are reachable, so rails@ and rustfs@ publish :3000 and :9000 on APP_PORT /
S3_PORT and tailscale serves http://127.0.0.1:<port>. No sidecar needed.
Overrides go in .unit-env/<slug>.share.env, which rails@ loads *after* .unit-env/<slug>.env — last wins both
in podman (--env joins over an earlier --env-file) and in systemd. It sets DOMAIN to the ts.net name,
DEV_HOSTS to WORKTREE_HOST so the desktop .localhost URL keeps working, RUSTFS_ENDPOINT to the tailnet
S3 host so presigned URLs resolve off-box, and TS_HOST_ENTRY for rails@'s extra --add-host. Overrides
must be container env, not .env.development: the units already set DOMAIN/RUSTFS_ENDPOINT and dotenv
never overwrites an existing ENV var. `off` truncates the file (never deletes it — podman's --env-file
is fatal on a missing path) and calls `tailscale serve reset`, which clears every serve on the machine.

## Identity / Ports (from local.toml.template, ID = WORKTREE_ID)

- Objects are named <prefix>-<slug>-<service>; shared ones use an underscore (<prefix>_npm_cache,
  <prefix>_proxy) precisely so per-worktree name matching cannot reach them.
- WORKTREE_HOST = <slug>.localhost; S3 = s3.<slug>.localhost; RustFS = s3-ui.<slug>.localhost; VNC =  
  vnc.<slug>.localhost. Traefik routes all.
- Ports: DB 55432+ID, Ruby debug 33000+ID, Neovim 17000+ID, Playwright 18888+ID,
  rails HTTP 13000+ID and rustfs 19000+ID (loopback, for wt:share only — Traefik uses the container network).
  There is no per-worktree compose override any more; a systemd drop-in
  (~/.config/containers/systemd/<prefix>-<svc>@<slug>.service.d/) is the equivalent.
- GEM*VOLUME = filial_shared_gems_ruby*<ver> (common across worktrees). node_modules per worktree  
  (<prefix>-<slug>-node-modules); npm cache shared via the ${PROJECT_PREFIX}_npm_cache volume.
- DEV_DB_NAME from config/database.yml via .scripts/dev-db-name.sh (postgres; empty → manual).

## Worktree stack (.container-config/quadlet/, installed by units:install)

- rails — build rails target; mount ../<slug>:/app + base .git (ro); shared volumes; db/redis over TCP  
  (PGHOST=db, REDIS_URL=redis://redis:6379/1 in .env); Traefik route WORKTREE_HOST→:3000; entrypoint  
  entrypoint-app.sh (db prepare/migrate) then bin/dev. Never fetches packages — that is deps@.  
  No home bind mount — ~ is the image's own (Dockerfile pre-creates the parents of the volumes mounted
  under it), because .home/<slug> holds Claude's OAuth token and rails runs agent-written code. Same
  for exec's transient container. Wants= playwright and nvim.  
  rails/nvim/playwright/claude use shared image tags (localhost/${PROJECT_PREFIX}/rails:ruby<ver>-node<ver>
  etc.) — one image per runtime combo across worktrees, never one per worktree. That is why no teardown
  removes images.
- deps — oneshot, rails image, dev network only; entrypoint-deps.sh runs `bundle check || bundle install`,
  installs foreman and retest (which bin/dev and test:rails_watcher would otherwise fetch from containers
  with no registry access), and `npm install` when node_modules/.deps-stamp (hash of node version +
  package.json + package-lock.json) is stale. Both checks are offline, so an unchanged worktree starts
  without the network. Firewall profile deps (registries only).
  rails@ Requires= it and it does NOT RemainAfterExit, so every rails start re-runs it — systemd's own
  Restart=on-failure restarts included (verified on the host): after a Gemfile or
  package.json change, `mise run restart`. Mounts only /app, GEM_VOLUME, node_modules and the npm cache — no
  home, .ssh, agent socket, .git or env files, since install scripts run in here. Output is in
  `journalctl --user -u <prefix>-deps@<slug>` (the container is --rm'd).
- db — postgres:16, optimized (fsync off, autovacuum off); port 127.0.0.1:${DB_PORT}:5432; initdb/restore-dump.sh
  run on init.
- redis — TCP 6379 on the dev network only, not published to the host; no persistence (--save '' --appendonly no).
- playwright — Dockerfile.playwright; run chromium.launchServer (headed via Xvfb + x11vnc+noVNC);  
  HEADLESS_SYSTEM_TESTS=1 for headless. server-side logic decides mode. Publish  
  127.0.0.1:${PLAYWRIGHT_HOST_PORT}:8888. Also run second interactive Chromium (always headed, same  
  display → same VNC page) with CDP :9222 loopback, socat republish :9223 for claude chrome-devtools MCP.  
  Egress firewalled (init-firewall-playwright.sh, NET_ADMIN): loopback + RFC1918 only — browser can't  
  reach internet (else it bypasses claude's firewall).
- rustfs — S3 storage, Traefik-routed. RUSTFS_CHECK_UPDATE=false (startup request to version.rustfs.com,
  which fw:show caught) and RUSTFS_TELEMETRY=off; each switch covers only its own outbound call.
- claude — NOT a unit. `docker compose run --rm` was a one-off interactive container and a systemd unit
  cannot be one (started detached, nothing on its TTY), so .scripts/podman-claude.sh holds the run args
  and starts rails + playwright first. claude target; no added capabilities, no sudo — its firewall is the
  host hook, profile agent, always enforce; worktree mounted at its host path  
  (not /app — the gitdir paths git records in master/.git/worktrees/ must resolve inside, or git and  
  gh-stack flag the worktree prunable; sibling worktrees are still prunable in here); home is a per-worktree bind mount (../.home/<slug>:/home/appuser), plain  
  ~/.claude (no override env var); entrypoint: add MCP  
  (pencil; chrome-devtools via socat loopback bridge 127.0.0.1:9222→playwright:9223 — CDP rejects  
  non-localhost Host header), rtk init, then claude --dangerously-skip-permissions.  
  Global memory: committed .container-config/CLAUDE.md mounted ro → /home/appuser/.claude/CLAUDE.md  
  (browser/MCP + rtk instructions); imports optional CLAUDE.local.md (gitignored  
  .home/<slug>/.claude/) for user-local instructions.  
  File memory: ../.container-config/claude-memory bind-mounted over  
  ~/.claude/projects/<host-path key>/memory (the old -app-<slug> dir is renamed once) — the one dir every worktree container shares.

## Egress firewall (.container-config/firewall/)

Every worktree container except playwright gets a default-deny egress firewall applied from OUTSIDE by an
OCI createRuntime hook (hook.sh). crun runs it in podman's rootless user namespace, where it is uid 0 with
CAP_NET_ADMIN over the container's netns, so it loads an nft table (inet wt_firewall) via
`nsenter -t <pid> -n nft -f -`. No container holds NET_ADMIN, so nothing inside — the agent, code rails
hot-reloads, an npm postinstall — can change its rules. A failing hook fails the start (fail closed).

- Wiring: units:install renders hook.json into .firewall/hooks.d/<prefix>-firewall.json. Units pass
  `GlobalArgs=--hooks-dir=…` plus `Annotation=<prefix>.firewall=<profiles>`,
  `<prefix>.firewall.mode=${FIREWALL_MODE}` and `<prefix>.firewall.networks=<every Network= it joins>`;
  podman-claude.sh and podman-wt.sh exec pass the same flags. The descriptor's env carries NETWORK_DIR
  (`podman info` GraphRoot + /networks, rendered by units:install).
  No descriptor = podman runs no hook and starts the container UNFIREWALLED without a word, so the
  descriptor is part of the stale-unit check (`up` refuses), doctor checks it, and podman-claude.sh /
  podman-wt.sh exec refuse to start without it. fw:show names any container that runs without a firewall.
- Profiles (comma list): none (rails, db, redis, rustfs, rustfs-init, transient exec), deps (deps@),
  agent (claude), agent,deps (nvim). Each but none is a <profile>.allow file: hostnames (resolved to IPv4 by
  the HOST at every start — no DNS from inside reaches the allowlist), IPv4/CIDRs, meta:github /
  meta:datadog-us5 (published ranges; need curl + jq on the host, skipped otherwise). claude adds
  CLAUDE_FIREWALL_ALLOW through the <prefix>.firewall.extra annotation. agent deliberately lacks rubygems.
- Always allowed: loopback, replies, the subnets of the annotated networks (dev + proxy: db, redis,
  rustfs, playwright, Traefik, aardvark DNS at the gateway), IPv6 link-local. Everything else, any port.
  Subnets come from netavark's <name>.json in NETWORK_DIR, NOT the netns: for UserNS=keep-id containers
  (rails, nvim, deps, claude) podman configures the network after the OCI create, so at createRuntime the
  netns has no routes yet — reading them left local=none and would have cut rails off from db. A unit
  joining a new network must add it to the networks annotation, or that network is unreachable.
- Modes: FIREWALL_MODE (mise.local.toml → .unit-env, default log) for the units; claude is always enforce.
  enforce rejects (icmpx admin-prohibited, so clients fail fast); log accepts but records — both write the
  final-verdict flows to dynamic sets blocked4/blocked6 (7d timeout) that fw:show reads; off loads nothing.
  A deps@ run is too short-lived to read back; its failures are in its journal.
- fw:show / fw:allow <svc> <host…> → .scripts/firewall.sh, via `podman unshare nsenter`. fw:allow adds to a
  running container's allow4 until its next start; persistent changes go in the .allow files or
  CLAUDE_FIREWALL_ALLOW. Host needs nft, nsenter, getent (doctor checks).
- Known gap: aardvark-dns forwards any name upstream, so DNS stays a narrow exfil channel. playwright keeps
  its own in-container firewall (init-firewall-playwright.sh, NET_ADMIN), which its browser cannot change.

GEM_VOLUME is shared across worktrees on the same ruby; node_modules is per-worktree. Networks:
<prefix>-<slug>-dev (per worktree, MTU 1400 — aliases db/redis/rustfs would collide on a shared one)
plus ${PROJECT_PREFIX}_proxy. Shared cache volumes mount with :U so podman chowns them to the container
user; GEM_VOLUME deliberately does not, so image copy-up still populates it.

Unit mechanics worth knowing before editing a template:
- A .network file generates <name>-network.service, so net@.network is <prefix>-net-network@<slug>.service.
  A bare Network= creates no dependency; Requires=/After= must name it.
- Quadlet does NOT expand ${VAR} itself. systemd does, from the service environment — so every file
  whose keys use ${VAR} loads .unit-env/<slug>.env under **[Service]** as well as [Container]. A
  [Container] EnvironmentFile becomes `podman run --env-file`, which reaches the process and not the
  unit. units:install refuses to install a template that gets this wrong (lint_env_expansion).
- Label=/Environment= values containing spaces must be quoted, or systemd splits ExecStart on the space
  and silently drops half a Traefik rule. Also linted.
- A Traefik regex backreference is written $${1}: systemd would expand ${1} away.
- podman will not create a missing bind-mount source the way the Docker daemon did; `up` preflights
  every Volume= source and seed-home.sh runs first.

## Proxy (.container-config/quadlet/, proxy.network + traefik/dozzle)

One Traefik v3.7 stack as user units (<prefix>-traefik, -dozzle). The dashboard is not part of it (see Dashboard).  
Docker-compat provider over podman's socket (`systemctl --user enable --now podman.socket`) —
verified end to end by `mise run verify`, exposedByDefault=false, entrypoint web:80, Traefik API :8080. Preserve encoded URL chars (S3).  
logs.localhost→Dozzle (live logs, all project containers, DOZZLE_FILTER=name=${PROJECT_PREFIX}).
The worktree units pull the proxy in via Wants=, so `up` needs no proxy step.  
Claude status: claude-status-hook.sh (v2: state/ts/rtk plus phase/event/message/tool/last_message), registered
per event idempotently by entrypoint-claude.sh into shared settings.json, writes
.container-config/status/<slug>.json (git-ignored); the dashboard reads it from disk. wt:rm cleans the file.
The dashboard's agent states: permission/question (◆, accent), working, idle, off, and for phase done (v1
waiting) either reply — the last message ends in `?` once trailing space, `)`/`]`, quotes and `*`/`_`/backtick are trimmed
(◆ waiting for reply, accent) — or your turn (yellow). permission/question/reply count as needing input and
notify when entered; your turn does neither. The hook is unchanged: the dashboard derives reply.  
Host ports (80/8080, the dashboard port, also nvim/ruby-debug in worktree stack) bind 127.0.0.1 only — Host-header routing would  
otherwise expose all worktrees + password-less VNC to LAN. Containers can't reach loopback-bound host ports, so  
Traefik has static IP PODMAN_TRAEFIK_IP (default 10.214.0.2, subnet PODMAN_PROXY_SUBNET 10.214.0.0/24 —
not 10.213, which docker's proxy held; netavark refuses a subnet already in use) on the proxy net;
worktree --add-host entries point WORKTREE_HOST/S3/UI there instead of host-gateway.
Rootless podman cannot publish :80 below net.ipv4.ip_unprivileged_port_start — `mise run doctor`
checks it and `mise run allow-ports` lowers it.
units:install removes orphaned rendered units of this prefix (marker line, template gone — how the old
<prefix>-home.container went) and check-stale reports them.

## Dashboard (.dashboard/)

- What: one page at http://wt.localhost:${WT_DASHBOARD_PORT} (default 7700) — worktrees, git/PR/stack state,
  units, containers, claude status, actions with streamed output, a task palette (`:`/Ctrl-K). ↑↓/k j open
  the previous/next worktree, Home End/g G the first/last (not while typing or in a dialog). Not routed through Traefik.
- Process: host unit <prefix>-dashboard.service, rendered by units:install into ~/.config/systemd/user from
  .container-config/systemd/dashboard.service. ExecStart `<mise> run dashboard:serve` (Falcon `--threaded
  --count 1` on 127.0.0.1:${WT_DASHBOARD_PORT}); DASHBOARD_MISE_DIR is prepended to PATH because `mise run`
  does not put mise on it and actions run `mise` by name. check-stale renders @@MISE@@ from the calling
  shell's `command -v mise`: keep one mise on PATH, or the unit reads stale until units:install.
- Lifecycle: `mise run dashboard [browser]` starts it, waits on /healthz, opens the page. Independent of the
  proxy: proxy:down/restart leave it; start_proxy and proxy:up start it; it stops via dashboard:stop,
  units:uninstall, destroy. Never enabled by units:install; dashboard:autostart on|off (or the page's switch)
  enables it to start at login.
- Security: loopback only. Every request (SSE included) needs an allowed Host (wt.localhost/localhost/127.0.0.1
  with the port — stops DNS rebinding); POSTs also need an allowed Origin and X-Dashboard-Token (stops other
  pages); a stale token (page from before a restart) → 403 + X-Dashboard-Reload. Every response carries
  X-Frame-Options DENY and CSP frame-ancestors 'none' (an agent's app page cannot frame it to lure clicks).
  No login, by the user's decision: single-user host. dashboard:isolation-check (also run by verify) proves
  no container reaches the port — exit 1 reached, 2 could not probe. Containers run agent-written code; the
  dashboard drives the host.
- Reading untrusted repos: GitSafety runs every background git/gh read with GIT_COMMON_DIR pointing at a
  host-private shadow ($XDG_RUNTIME_DIR/<prefix>-dashboard/gitcommon, 0700; never mounted into a container).
  Its config is regenerated, when the real master/.git/config's bytes change, from one capped read of that
  file (regular files only) through an allowlist — core format keys, extensions.objectformat/refstorage,
  remote.*.url/fetch/gh-resolved, branch.*.remote/merge — so no filter, include, fsmonitor, hooksPath or
  worktreeConfig a container writes ever reaches git, however it races the read. git lists the file (one
  `git config --list`); the dashboard writes the kept entries in one pass, and more than 2,000 of them fails
  closed, so a bloated config cannot hold the pollers. objects, refs, packed-refs,
  HEAD, shallow, gh-stack and reftable are symlinked; info/ and hooks/ are not. worktrees/ is a real directory
  with a real directory per worktree whose entries link to the real admin files (no config.worktree): gh-stack
  lstats both levels and refuses symlinks. It follows worktrees being added and removed. Overrides stay as
  defence in depth (core.fsmonitor=false, core.hooksPath=/dev/null, diff.ignoreSubmodules=all,
  submodule.recurse=false, GIT_OPTIONAL_LOCKS=0) and git status passes --ignore-submodules=all: a
  submodule's own config is never sanitized. A shadow that cannot be built fails the read closed (`?`) —
  else a worktree's config becomes code the host runs unattended. It never runs `mise env`
  (a worktree's mise.local.toml is container-writable); ports/hosts come from .unit-env/<W>.env. Those files and
  the claude status files are read as hostile: regular files only (a FIFO or symlink is refused, opened
  O_NONBLOCK|O_NOFOLLOW), at most 1 MiB, JSON fields type-checked (nested rtk too: each a finite number in
  0…1e15, else dropped from the chip); a bad file is absent for that worktree only.
  The palette lists tasks via `mise tasks --json` at the workspace root, never in a worktree.
- Refresh: local sources every 1/3/5/60 s. GitHub only while a page holds the SSE stream (60 s hot / 300 s),
  on connect/focus (coalesced 10 s) and after GitHub-touching actions (never dropped). A newly viewed
  worktree's stack is read at once.
- Actions: argv only, no shell. Each child runs in `systemd-run --user --scope --collect` and writes
  stdout+stderr to $XDG_RUNTIME_DIR/<prefix>-dashboard/jobs/<id>.log (0600, appended; the dashboard tails it),
  never a pipe, so a dashboard stop or restart leaves it running (its output after that is lost; a job's log
  goes when the job leaves the last 20, and all at the next start). The tailer (runner/log_tail.rb) keeps a
  log small: read past 8 MiB and caught up → emptied in place (a line written in that instant can be lost);
  16 MiB on disk while the child runs → emptied, the unread part dropped, and the job shows
  "… output dropped (log over 16 MiB)". It looks at the size every read and every 1 ms of consuming, so a log
  peaks near 16 MiB plus what the child writes between two looks (measured: ~19 MiB under `yes`; up to
  0.1 s of output when a child bursts after a pause). After the child exits only the last 8 MiB unread is
  read. A child left writing while the dashboard is down has no tailer, so only the tmpfs's size caps that
  output. Every child (actions and reads) gets
  exactly the environment the dashboard had before Bundler set up (captured at boot; no BUNDLE_*, RUBYOPT
  -rbundler/setup or vendor GEM_HOME), plus for actions stdin /dev/null, NO_COLOR=1 and the session env
  (SSH_AUTH_SOCK DISPLAY WAYLAND_DISPLAY XDG_CURRENT_DESKTOP XDG_RUNTIME_DIR KITTY_LISTEN_ON) read per child
  from `systemctl --user show-environment`. lib.sh push_session_env pushes SSH_AUTH_SOCK, DISPLAY,
  WAYLAND_DISPLAY, XDG_CURRENT_DESKTOP and KITTY_LISTEN_ON from the calling shell in `mise run dashboard`,
  start_proxy and proxy:up (not XDG_RUNTIME_DIR: the user manager has it natively).
  Scopes: one job per worktree; workspace jobs one at a time. Palette tasks run in the picked worktree, except
  workspace-level ones (wt, wt:rm, units:install/uninstall, dashboard:autostart/stop, clean, destroy, proxy:*,
  allow-ports), which run at the root as workspace jobs; units:uninstall, dashboard:stop, wt:rm and
  db:dump:clear ask in the page first. Keeps the last 20 jobs; per job 5000 lines and 4 MiB (oldest lines go
  first), 64 KiB per line. Cancel sends TERM, then KILL after 3 s, to the job's host-side process group: for a
  command run through `podman-wt.sh exec` that stops the host's `podman exec`, not necessarily the process
  inside the rails container (a test run there may go on). Terminal actions go through .scripts/newterm.sh.
  podman-wt.sh exec passes -t only when stdin is a terminal, since the dashboard streams with stdin closed;
  units-env.sh keeps a still-live previous SSH_AGENT_SOCK when the caller has no agent socket.
- Rule: the dashboard changes state only through mise tasks (and their scripts); never reimplement one in Ruby.
- Test: `mise run dashboard:test` — minitest on captured fixtures plus the hook shell test; needs no podman,
  systemd, gh or network.

## mise tasks (.mise/config.toml)

- up(u)/stop(s)/down/restart/status/logs/exec/destroy: lifecycle. up starts rails and systemd resolves
  the rest through Requires=/Wants=, gated on db/redis/rustfs being *healthy*. stop keeps volumes; down
  deletes this worktree's three and prompts, defaulting to No. destroy nukes all <prefix>[-_]* resources,
  the rendered units and the folder (type 'destroy' to confirm).
- units:install/units:uninstall/units:env, doctor, verify, verify:spike, allow-ports: unit and host
  management. `up` refuses to start when an installed unit no longer matches its template. verify also checks
  the dashboard's /healthz and runs dashboard:isolation-check (1 → fail, 2 → warn).
- dashboard/dashboard:serve/dashboard:stop/dashboard:autostart/dashboard:test/dashboard:isolation-check;
  see Dashboard above.
- rails/console(c)/ci: all route through `podman-wt.sh exec`, which uses the running rails container
  when it is up and a transient one otherwise. The transient container carries
  --label traefik.enable=false, or Traefik load-balances the worktree host onto something not serving
  :3000 (intermittent 502s). EXEC_FRESH=1 forces the transient path (ci, test:rails_watcher — quitting a
  watcher attached to the rails container would take the dev server down); EXEC_ENV passes extra env.
- test(t) = test:rails then test:javascript, sequential (array run, not depends — depends is parallel).  
  test:rails(tr)/test:rails_watcher(trw, retest)/test:rails_system(trs) forward args to bin/rails;  
  test:javascript(tj)/test:javascript_watcher(tjw) forward args to npx vitest (Vitest + jsdom, no DB, so no depends=up).  
  All go through `podman-wt.sh exec`.
- nvim(v) attaches to the nvim server; its config comes from
  <prefix>_nvim_config, a writable named volume shared by every worktree, so you
  configure nvim from inside the container once. Set NVIM_CONFIG_DIR in the
  workspace-root mise.local.toml to bind a host config read-only instead --
  units-env.sh turns that choice into NVIM_CONFIG_MOUNT (the whole mount spec,
  because the two cases differ in source and flags and Quadlet cannot branch)
  plus NVIM_CONFIG_SOURCE, which the entrypoint reports. Plugins are a separate
  volume, <prefix>_nvim_share.
- claude(ai)/claude:newterm(ai:newterm)/claude:rebuild, db:dump/db:dump:clear, tags, proxy:*,
  clean. db:dump writes .container-config/db-dumps/, which is also the restore path: db@'s initdb hook
  restores <dbname>.dump on a first start against an empty volume and rustfs-init@ untars
  rustfs_data.tar.gz. clean first offers wt:rm for linked worktrees whose branch is finished — a merged
  PR (gh) containing the worktree's HEAD, or an upstream deleted on origin (after `fetch --prune`) —
  skipping any with uncommitted changes; prompts, defaulting to No; branches are kept. It then removes
  artifacts of worktrees that no longer exist, plus image tags no live
  worktree's .unit-env/<slug>.env references — a worktree missing that file disables the image sweep
  entirely rather than having its images look stale.
- fw:show/fw:allow → .scripts/firewall.sh; see Egress firewall above.
- hooks:backup [hook…]/hooks:restore, plus the check `up` and doctor run → .scripts/git-guard.sh. claude and
  nvim mount master/.git writable (commits, gh-stack's upstream config, hook editing), so the spots where a
  container write becomes code host git runs cannot be read-only; this detects changes instead, warning only:
  every non-.sample hook in master/.git/hooks must match its copy in .container-config/git-hooks/ (git never
  tracks hooks — pre-push, the push data-loss guard, exists nowhere else — and a lefthook launcher rewrite
  shows up too); master/.git/config names must match CONFIG_ALLOWED (names only, never values: remote URLs
  can hold tokens); every linked worktree's .git file must point into master/.git/worktrees/. backup copies
  installed → tracked (commit afterwards); restore keeps an installed hook that differs unless FORCE=1.
- log:trim: truncate (never unlink — a container may hold it open) any */log/\*.log over 100 MB across
  every worktree. log/test.log is appended by every run and never rotated; a depends of the test:rails\*
  tasks. Container stdout is capped separately by the x-logging anchor (json-file, 20m x 3) in both
  unit templates (LogDriver=k8s-file, LogOpt=max-size=20m). Applies on the next up (recreate), not
  stop/start. Note k8s-file means container stdout is NOT in the journal: `journalctl --user -u <unit>`
  shows systemd and podman messages, `podman logs` shows the app. So logs/proxy:logs follow
  `podman logs -f`, except deps and rustfs-init: oneshots whose output is in the journal (passthrough and
  podman's default journald driver) and whose --rm'd container is gone once they finish.
- claude:template:promote/claude:template:apply: sync the Claude config set (agents, hooks, skills,  
  settings, plugin records) between a worktree home and .container-config/home-template — promote pushes  
  this worktree's config to the template (merges plugin records unless --replace); apply copies the  
  template onto this worktree's home (or --all for every home); apply never touches credentials,  
  sessions, or other state.
- claude runs in the current window; CLAUDE_NEW_TERM=1 or claude:newterm delegates to
  .scripts/claude-newterm.sh, a wrapper over .scripts/newterm.sh (shared with the dashboard), which detects the
  host terminal (env fingerprint, then process tree) then escalates: new tab
  (tmux/kitty/wezterm/konsole/gnome-terminal/xfce4-terminal/terminator/iTerm2) → new window of that same terminal
  → new window of any emulator found ($TERMINAL first, then kitty, wezterm, ghostty, alacritty, foot, konsole,
  gnome-terminal, xfce4-terminal, terminator, xterm) → current window only when nothing is launchable and the
  script itself runs on a TTY.

## Host-side Rails DB access

db publishes on 127.0.0.1:${DB_PORT}. Template sets host-shell only                                               
PGHOST=127.0.0.1/PGPORT=${DB_PORT}/PGUSER/PGPASSWORD. Host bin/rails/psql reach container DB via TCP. Inside  
containers, .container-config/.env wins (PGHOST=db over the dev network). System tests run on host against container browser  
(PLAYWRIGHT_HOST=ws://localhost:port, APP_HOST=host.containers.internal — podman writes both that and
host.docker.internal into /etc/hosts).

## System tests (Playwright over VNC)

Use capybara-playwright-driver to Playwright browser server in playwright service. Container runs Xvfb + x11vnc +
noVNC; watch at http://vnc.<worktree>.localhost.

- Playwright >= 1.54: connect_to_playwright_server removed. Use connect_to_browser_server. Headless/Headed  
  decided server-side via chromium.launchServer.
- HEADLESS_SYSTEM_TESTS drives both paths: container launchServer (env) and client headless option (local).
- PLAYWRIGHT_HOST (.container-config/.env) = ws://playwright:8888/connect; /connect matches entrypoint launchServer.
- Playwright version derived per worktree from Gemfile.lock (playwright-version.sh → PLAYWRIGHT_VERSION →  
  image tag v<ver>-noble + npm playwright-core). Gem bump → next `up` builds the matching image. `up` warns  
  when PLAYWRIGHT_VERSION is empty (stale mise.local.toml).
- Infra changes require build & up for playwright.

## Conventions

- Dockerfile per service: if a custom image is needed, use .container-config/Dockerfile.<service> and add a
  case to .scripts/podman-build.sh. No multi-stage additions to the base Dockerfile. Mount entrypoint
  scripts via volume (edits apply on the next start, no rebuild). Keep images decoupled.
- Env vars in Ruby: use ENV.fetch("KEY", default). Avoid ENV["KEY"] or .presence unless empty string specifically
  needed. Consistent ENV.fetch in config/initializers.

## Gotchas

- Worktree removal must stay scoped. `git worktree prune` deletes the admin entry of every worktree whose dir  
  isn't found on disk — from a partial filesystem view (e.g. a container mounting only master/ + one worktree)  
  that is ALL of them, purging the whole registry and disconnecting every worktree from its branch. wt:rm uses  
  scoped `git worktree remove` and aborts on a partial view; keep it that way, never a blanket prune. To recover  
  a purged registry: rebuild each master/.git/worktrees/<name>/ (commondir `../..`, gitdir → the worktree's .git  
  file, HEAD → its branch), then `git worktree repair` and `git reset` in each worktree.
- ssh-agent into nvim/claude: SSH_AGENT_SOCK (.mise/config.toml) is the host's $SSH_AUTH_SOCK, bind-mounted
  at /tmp/ssh-agent.sock with SSH_AUTH_SOCK pointing there, so the agent passes straight through — under
  keep-id the host user maps to uid 1000 inside, so the socket's ownership works. rails does not get it
  (it never did under compose either). units:env validates the path and falls back to /dev/null when it is
  not a live socket: a stale $SSH_AUTH_SOCK was harmless under docker, which created the missing bind
  source, but podman refuses the whole container with "statfs: no such file or directory". No agent →
  /dev/null mount, containers still start, ssh falls back to a passphrase prompt. This branch is Linux-only;
  the old macOS /run/host-services path is gone with Docker Desktop.
- mise resolution: base worktree must live under wrapper root (adopt.sh moves + symlinks).
- Firewall allowlists resolve hostnames once per container start, so a CDN that rotates addresses can
  start rejecting a long-lived container (claude, nvim) mid-session; fw:allow or a restart refreshes it.
- Browse the app at WORKTREE_HOST on :80, never rails:3000. The app's development.rb pins
  default_url_options to DOMAIN but keeps the request's port, so a page on rails:3000 renders
  *_url links (ActiveStorage images, e.g. the patient photo) as http://<DOMAIN>:3000/… —
  cross-origin (CSP blocks it) and unrouted. The VNC Chromium starts at http://${WORKTREE_HOST};
  inside playwright, Chromium resolves *.localhost to loopback itself (ignoring --add-host), and a
  socat shim forwards loopback :80 to Traefik.
